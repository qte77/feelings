Jev coding-gate results

Can Jev act as a fast check on a code change, before the slow checks (tests, lint, CI) run? Each runner answers four questions about a change as probabilities. Jev is called with and without BAML; Claude runs through the claude CLI as the baseline in the earlier pilot below.

Pilot results per runner
  • Wrongly blocked: share of good changes the fast first check would reject. Caught: share of bad changes it rejects.
  • Blocked by firewall: on 2026-09-23 TypeSafe's Cloudflare firewall answered 4 changes with HTTP 403 on every try; from 2026-09-24 the same changes went through. Runners are always scored on the changes all of them answered.
  • Cost per check: Claude's is what the CLI reports at list price. Jev's is measured input tokens × $0.042 per million (typesafe.ai); TypeSafe publishes no output price, so it covers input only. The BAML runner doesn't log usage.
  • Per-request time is not logged by the BAML runner. End-to-end, one check took p50 0.90 s / p95 3.15 s without BAML and 0.86 s / 2.94 s with it (10 runs each, 2026-09-23). Claude hasn't been timed the same way yet.
  • Bars passed counts the pass bars (AUC, repeat agreement, false rejects, speed). Claude runs once per change, so its agreement bars aren't measured.
