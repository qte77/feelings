Jev coding-gate results

Can Jev act as a fast check on a code change, before the slow checks (tests, lint, CI) run? Each runner answers four questions about a change as probabilities, on 60 labelled changes taken from analyze-stock-kpi. Jev is called with and without BAML; Claude runs through the claude CLI as the baseline.

How well each runner separates good from bad changes

AUC per question: 1.0 ranks every bad change above every good one, 0.5 is guessing. Scored on each runner's first answer, so Jev's five repeats and Claude's single run compare fairly. The axis starts at 0.85.

All numbers

Results per runner
  • Wrongly blocked: share of good changes the fast first check would reject. Caught: share of bad changes it rejects.
  • Blocked by firewall: TypeSafe's Cloudflare firewall answers some changes with HTTP 403 on content alone, every time. Jev is scored on the rest.
  • Per-request time is not logged by the BAML runner. End-to-end, one check took p50 0.90 s / p95 3.15 s without BAML and 0.86 s / 2.94 s with it (10 runs each).
  • Bars passed counts the pilot's pass bars (AUC, repeat agreement, false rejects, speed). Claude runs once per change, so its agreement bars aren't measured.
